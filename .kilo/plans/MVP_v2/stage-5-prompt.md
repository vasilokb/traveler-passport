### 1. sw.js — обновление Service Worker

Обновить `sw.js` для корректной работы с v2:

#### 1.1. Обновить версию кэша

Заменить:
```js
var CACHE_NAME = 'belarus-passport-v1';
```
На:
```js
var CACHE_NAME = 'belarus-passport-v2';
```

#### 1.2. Добавить `skipWaiting()` в `install`

После `cache.addAll(ASSETS)` добавить вызов `self.skipWaiting()`, чтобы новый SW активировался немедленно, не дожидаясь закрытия вкладок со старым:

```js
self.addEventListener('install', function (event) {
  event.waitUntil(
    caches.open(CACHE_NAME)
      .then(function (cache) {
        return cache.addAll(ASSETS);
      })
      .then(function () {
        return self.skipWaiting();
      })
  );
});
```

#### 1.3. Добавить `clients.claim()` в `activate`

В начало обработчика `activate` (перед `event.waitUntil`) добавить `self.clients.claim()`, чтобы SW перехватил управление всеми открытыми вкладками сразу:

```js
self.addEventListener('activate', function (event) {
  event.waitUntil(
    caches.keys().then(function (keys) {
      return Promise.all(
        keys.filter(function (key) { return key !== CACHE_NAME; }).map(function (key) { return caches.delete(key); })
      );
    })
  );
  self.clients.claim();
});
```

Обработчик `activate` уже содержит очистку старого кэша — он корректный, нужно только добавить `self.clients.claim()` после `event.waitUntil(...)`.

⚠️ **Важно:** Сохраняй ES5-стиль написания кода (анонимные функции `function () {}` вместо стрелочных, `var` вместо `let/const`) внутри обработчиков SW, как это сделано в текущей версии `sw.js`.

#### 1.4. Проверить актуальность массива `ASSETS` и пути

⚠️ **Критично:** Чтобы PWA корректно работало при деплое в любую подпапку (например, на GitHub Pages), пути в массиве `ASSETS` должны быть относительными (без ведущего слэша `/`). Абсолютные пути типа `/index.html` сломают кэширование (404), если приложение развёрнуто не в корне домена.

Рекомендованный список:
```js
var ASSETS = [
  './',           // Относительный корень — обязателен для офлайна при заходе по адресу подпапки без index.html
  'index.html',   // Должен совпадать со значением start_url в manifest.json — без ведущего слэша!
  'style.css',
  'app.js',
  'manifest.json'
  // Иконки: допиши сюда точные имена файлов иконок из manifest.json, убрав из путей ведущий слэш!
];
```

⚠️ **Запрещены:** пустая строка `''` (вызывает `TypeError` в `cache.addAll` на некоторых WebView), абсолютный путь `'/'` (ломает деплой в подпапки). Разрешены только `'./'` и явные имена файлов.

⚠️ **Оба ключа обязательны:** `'./'` и `'index.html'` — разные URL-ключи для Service Worker. Без `'./'` офлайн-заход по адресу `.../subfolder/` выдаст 404. Без `'index.html'` прямой переход на `.../index.html` в офлайне выдаст 404. **Не объединяй и не удаляй ни один из них — они обязаны сосуществовать как два отдельных ключа кэша.**

⚠️ **При копировании путей к иконкам из `manifest.json`** в массив `ASSETS`, обязательно убирай ведущий слэш (например, вместо `/icon-192.png` пиши `icon-192.png`), чтобы SW не упал с ошибкой 404 при деплое в подпапку (GitHub Pages).

⚠️ **Не выдумывай имена файлов:** Строго сохрани все текущие файлы иконок, которые уже прописаны в существующем `sw.js`, но принудительно очисти их от ведущих слэшей (например, `/icon-192.svg` → `icon-192.svg`). Любой выдуманный файл, вернувший 404, полностью заблокирует установку Service Worker.

⚠️ **ИИ-инструкция:** Перед формированием массива `ASSETS` обязательно прочитай файл `manifest.json` и посмотри, какие именно файлы иконок (расширения `.png` / `.svg`) и по каким путям там задекларированы, а также чему равен `start_url`. Перенеси имена файлов иконок в `ASSETS` с абсолютной точностью.

Если в проекте появились новые статические файлы, необходимые для работы приложения — добавить их в массив. **Неполный массив приведёт к тому, что `skipWaiting()` обновит логику SW, но сами файлы останутся из старого кэша.**

⚠️ **Имена файлов иконок** (расширения `.svg` / `.png`, пути) должны строго соответствовать реальным файлам в проекте. Сверяй их с `manifest.json`. Не заменяй расширения вслепую — если хотя бы один файл из `ASSETS` вернёт 404, весь Service Worker упадёт при установке.

### 2. app.js — обновление Service Worker интеграции на странице

#### 2.1. Добавить слушатель обновления SW (с защитой от ложного тоста)

Найди в коде `app.js` место, где происходит регистрация Service Worker (`navigator.serviceWorker.register`). Интегрируй логику отслеживания обновления **рядом с регистрацией** (либо в конец `init()`, если регистрация инкапсулирована там). Главное — чтобы слушатель `controllerchange` был навешан в том же контексте, что и регистрация SW, а не в изолированном блоке:

⚠️ **Область видимости:** Переменные `hasControllerOnLoad` и `updateToastShown`, а также слушатель `controllerchange`, должны быть объявлены **в самом конце `app.js`**, после строки `document.addEventListener("DOMContentLoaded", init);` — строго **вне любых функций**, чтобы они инициализировались ровно один раз при загрузке скрипта и не сбрасывались при повторных вызовах. Используй проверку `typeof navigator` для защиты от падения в изолированных контекстах:

```js
// СТРОГО на верхнем уровне app.js, вне любых функций:
if (typeof navigator !== 'undefined' && 'serviceWorker' in navigator) {
  var hasControllerOnLoad = !!navigator.serviceWorker.controller;
  var updateToastShown = false;
  navigator.serviceWorker.addEventListener('controllerchange', function () {
    if (hasControllerOnLoad && !updateToastShown) {
      updateToastShown = true;
      showToast("Приложение обновлено");
    }
  });
}
```

⚠️ **Почему `hasControllerOnLoad`:** Событие `controllerchange` срабатывает при *любой* смене контроллера, включая самую первую установку SW (когда пользователь впервые открывает сайт). Без проверки `hasControllerOnLoad` тост «Приложение обновлено» выскочит у новых пользователей, которые ничего не обновляли. Флаг `!!navigator.serviceWorker.controller` на момент загрузки страницы равен `true` только если страницой уже управлял предыдущий SW — это и есть признак реального обновления.

⚠️ **Почему `updateToastShown`:** В некоторых браузерах при быстрой перезагрузке `controllerchange` может выстрелить дважды. Предохранитель гарантирует, что тост появится ровно один раз за сессию.

⚠️ **Категорически запрещено** добавлять `window.location.reload()` внутри обработчика `controllerchange`. Автоматическая перезагрузка может вызвать бесконечный цикл в некоторых версиях Chrome/WebView. Обработчик должен **только** вызывать `showToast()`.
