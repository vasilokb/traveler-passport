## Что нужно реализовать

### 1. Онбординг (первый вход)

**Условие показа:** онбординг появляется **только при первом входе** — когда в `localStorage` ещё нет записи `travelerPassport` (или поле `onboardingComplete` в `state` отсутствует/`false`).

**UI:** полноэкранный оверлей поверх контента с:
- Приветственный текст (например: «Добро пожаловать в Паспорт путешественника!»).
- Поле ввода имени (`<input type="text" placeholder="Ваше имя">`).
- Кнопка **«Продолжить»** — сохраняет введённое имя в `state.travelerName`.
- Кнопка **«Пропустить»** — сохраняет дефолтное значение `state.travelerName = "Белорусский путешественник"`.
- Обе кнопки закрывают оверлей и устанавливают `state.onboardingComplete = true`.

**Требования:**
- Поле ввода и обе кнопки — не менее 44×44px тап-область.
- Имя может быть любой длины, но разумно ограничить `maxlength="50"`.
- После онбординга пользователь видит Каталог (или ту вкладку, которая была `currentTab` по умолчанию).

### 2. Экран Профиля (`#tab-profile`)

Заменить заглушку «Профиль (скоро)» на полноценный экран с вертикальным скроллом. Содержимое (сверху вниз):

**Блок имени:**
- Отображается `state.travelerName`.
- Рядом — иконка карандаша или кнопка «Редактировать» (не менее 44×44px).
- По тапу — имя превращается в `<input type="text">` с текущим значением. Кнопка «Редактировать» **скрывается**. Появляются кнопки «Сохранить» и «Отмена». После сохранения — `state.travelerName` обновляется, `saveState()` вызывается, инпут заменяется обратно на текстовое отображение имени.
- **Клавиатура:** `Enter` — сохранить, `Escape` — отменить.
- Если имя — дефолтное «Белорусский путешественник», визуально подсказать, что его можно изменить.

**Блок общей статистики:**
- Крупный текст: **«X из 57»** (где X — количество посещённых городов).
- Общий прогресс-бар (заполнен на X/57).

**Блок прогресса по регионам:**
- 7 строк, по одной на регион. Каждая строка:
  - Название региона (из `REGIONS.name`).
  - Цветная полоска прогресс-бара (цвет — из `REGIONS.color`).
  - Текст: «Y из Z» (где Y — посещённые города региона, Z — общее количество городов в регионе).
- Порядок регионов — как в массиве `REGIONS`.

**Блок Хроники визитов:**
- Заголовок «Хроника посещений».
- Список посещённых городов. Каждый элемент:
  - Название города (из `CITIES.name`).
  - Дата визита в формате **ДД.ММ.ГГГГ** (например: `12.04.2025`). Дата берётся из `state.visitedCities[cityId].date` (хранится в `YYYY-MM-DD`).
- Если посещённых городов нет — заглушка: *«Вы пока не посетили ни одного города. Отправляйтесь в путь!»*

### 3. Хроника: сортировка

Список Хроники сортируется:
1. **По дате визита** — от новых к старым (убывание).
2. **При совпадении дат** — по названию города по алфавиту (возрастание). Используй `localeCompare` с явным указанием русской локали: `cityA.name.localeCompare(cityB.name, 'ru')`. Дефолтный `localeCompare` без локали может некорректно обрабатывать буквы «Ё» и «Й» в некоторых браузерах.

Пример правильного порядка:
```
Борисов — 15.05.2026
Мир — 12.04.2026
Несвиж — 12.04.2026      ← та же дата, что у Мира, но «Н» > «М» по алфавиту? Нет: М < Н, поэтому Мир первым
```
Верный порядок для одинаковой даты:
```
Борисов — 15.05.2026
Мир — 12.04.2026
Несвиж — 12.04.2026
```

### 4. Реактивность статистики

При любом изменении `state.visitedCities` (toggle в Каталоге) статистика на экране Профиля должна пересчитываться. Это достигается одним из способов:
- Перерендер Профиля при каждом переключении на вкладку `profile` (рекомендуется — проще и надёжнее).
- Или вызов `renderProfile()` из toggle-механики Каталога.

**Рекомендуемый подход:** рендерить содержимое Профиля заново при каждом переключении на эту вкладку. В функции переключения вкладок — сначала вызови `renderProfile()` (если целевая вкладка `profile`), затем покажи секцию. Так не нужно тянуть зависимости между экранами, и данные всегда актуальны.

## Изменения в style.css

- Стили оверлея онбординга: `position: fixed; top: 0; left: 0; width: 100%; height: 100%; z-index: 1000;`. Оверлей **полностью перекрывает** весь интерфейс, включая Tab Bar — пользователь не может переключить вкладку, не завершив онбординг. Фон — белый или полупрозрачный, содержимое центрировано.
- Стили Профиля: имя, статистика, прогресс-бары, хроника.
- Прогресс-бары: реализовать через CSS (`background` для заполненной части, `width` в процентах). **И подложка, и заполнитель** должны иметь одинаковый `border-radius` (например, 8px), а подложка — `overflow: hidden`. Без этого при 100% заполнения цветная полоса вылезет за скруглённые края трека.
- Хроника: список с разделителями или карточками, удобный для скролла.

## Локальная дата (напоминание)

При форматировании даты для отображения в Хронике (из `YYYY-MM-DD` в `ДД.ММ.ГГГГ`) — это просто переформатирование строки, проблема UTC не актуальна. Но если где-то нужна «текущая дата» — используй `new Date().toLocaleDateString('sv-SE')`, не `toISOString()`.
