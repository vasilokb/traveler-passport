# Промпт: Этап 1 — Каркас, справочник городов, Каталог

Создай базовый каркас мобильного веб-приложения «Паспорт путешественника по Беларуси». Это Этап 1 из 6. Результат этого этапа — рабочий Каталог городов с переключением вкладок и сохранением состояния в localStorage.

---

## Структура файлов

Создай ровно **3 файла** в корне проекта (`F:\projects\traveler-passport\`):

1. **`index.html`** — разметка
2. **`style.css`** — стили
3. **`app.js`** — логика и данные

Никаких библиотек, фреймворков, CDN-ссылок. Чистые HTML/CSS/JS.

## index.html

Главный контейнер: `width: 100%`, `max-width: 430px`, центрирован по горизонтали на широких экранах. Адаптивен вплоть до 320px (iPhone SE и старые Android). Никакого `min-width` — контейнер должен сжиматься на узких экранах.

Внутри контейнера — **4 секции** (экраны вкладок), одновременно видима только одна:
- `#tab-passport` — заглушка с текстом «Паспорт (скоро)»
- `#tab-catalog` — Каталог городов (основная рабочая секция)
- `#tab-map` — заглушка с текстом «Карта (скоро)»
- `#tab-profile` — заглушка с текстом «Профиль (скоро)»

Внизу — фиксированный **Tab Bar** с 4 кнопками: «Паспорт», «Каталог», «Карта», «Профиль». Активная вкладка визуально выделена. По умолчанию активна вкладка «Каталог».

## style.css

### Обязательные правила:
- Все active-элементы (кнопки, строки городов) — **не менее 44×44px** по размеру тап-области.
- Шрифт — системный (sans-serif). Базовый размер — 16px.
- Цветовая схема — светлая, чистая. Фон — белый или близкий. Текст — тёмно-серый/чёрный.
- Tab Bar — фиксирован внизу, не скроллится с контентом.
- Секции-вкладки скроллятся вертикально, если контент не помещается.
- На широких экранах (десктоп) — контентная область по центру, фон вокруг — нейтральный серый, чтобы была видна «мобильная рамка».

### Каталог:
- Заголовки регионов — жирные, с отступами сверху.
- Строки городов — кликабельные, с визуальным откликом (hover/active).
- Посещённые города — визуально выделены (например, зелёная галочка или цветной кружок слева от названия).
- Непосещённые — нейтральный стиль.

### 2. Справочник CITIES

Массив из **57 объектов**. Каждый город имеет поля: `id`, `name`, `region`, `lat`, `lon`, `description`.

**Требования к `id`:** стабильный латинский идентификатор, URL-safe, без пробелов и дефисов (кроме визуально оправданных). Примеры: `minsk`, `nesvizh`, `mir`, `david_gorodok`.

**Требования к `description`:** одно-два предложения туристического характера на русском языке. Информативные, не шаблонные. Генерируются тобой — каждый город должен получить уникальное описание, отражающее его достопримечательности или характер.

### 3. Навигация

Глобальное состояние — объект `state`:

```js
let state = {
  currentTab: 'catalog',
  travelerName: 'Белорусский путешественник',
  visitedCities: {}
};
```

Функция переключения вкладок: по клику на кнопку Tab Bar → скрыть все секции, показать нужную, обновить активную кнопку.

### 4. localStorage

- При загрузке страницы: проверить наличие данных в `localStorage` под ключом `travelerPassport`. Если есть — распарсить и загрузить в `state`. Если нет — инициализировать `state` значениями по умолчанию.
- Функция `saveState()` — сериализует `state` в JSON и записывает в `localStorage` под ключом `travelerPassport`.
- Вызывать `saveState()` после каждого изменения `state`.

### 5. Рендер Каталога

Функция `renderCatalog()`:
- Очищает содержимое `#tab-catalog`.
- Перебирает `REGIONS`, для каждого создаёт заголовок-группу.
- Внутри группы — перебирает `CITIES`, отфильтрованные по `region`.
- Для каждого города создаёт строку с названием.
- Если `city.id` есть в `state.visitedCities` — визуально отмечает строку как посещённую (добавляет CSS-класс `visited`).

**Делегирование событий:** обработчик клика на строки городов реализуй через делегирование событий на внутреннем контейнере `#catalog-list` (список городов внутри `#tab-catalog`), а не 57 отдельных слушателей. Внутри обработчика используй `event.target.closest('.city-item')` — это гарантирует, что клики по заголовкам регионов, шапке каталога и будущим фильтрам не вызовут toggle:

### 6. ⚠️ Временная toggle-механика (УДАЛЯЕТСЯ на Этапе 4)

По клику на строку города в Каталоге:
- Если город **не** в `state.visitedCities` → добавить: `state.visitedCities[cityId] = { date: today }`, где `today` — **локальная** дата в формате `YYYY-MM-DD`.
- Если город уже в `state.visitedCities` → удалить: `delete state.visitedCities[cityId]`.

**⚠️ Важно: локальная дата, не UTC.** Не используй `new Date().toISOString().split('T')[0]` — при UTC+3 после 21:00 дата перескочит на завтра. Используй:
```js
const today = new Date().toLocaleDateString('sv-SE'); // 'sv-SE' даёт формат YYYY-MM-DD в локальной зоне
```
Или вручную через `getFullYear()`, `getMonth()`, `getDate()` с `padStart(2, '0')`.
- Вызвать `saveState()`.
- Перерисовать Каталог: `renderCatalog()`.

**Это временная механика для отладки. Она противоречит финальному MVP, где отметка происходит только через карточку города с выбором даты. Будет полностью удалена на Этапе 4.**

### 7. Инициализация

Функция `init()`:
- Вызывается при `DOMContentLoaded`.
- Загружает `state` из localStorage (или инициализирует дефолтными значениями).
- Рендерит Каталог.
- Устанавливает активную вкладку `catalog`.
