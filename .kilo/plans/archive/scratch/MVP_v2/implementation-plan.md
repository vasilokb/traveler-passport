# MVP v2 — Implementation Plan

## Контекст

Рефакторинг PWA «Паспорт путешественника по Беларуси» из трекера посещений в инструмент планирования и заметок.

**Спецификация:** `.kilo/plans/MVP_v2/MVP_v2.md`
**Текущая кодовая база:** `index.html` (112 строк), `style.css` (1209 строк), `app.js` (1251 строка)

## Дельта изменений v1 → v2

| Аспект | v1 | v2 |
|--------|----|----|
| Tab Bar | 4 вкладки | **3 вкладки** (Каталог удалён) |
| Состояния города | 2: непосещён, посещён | **3**: непосещён, посещён, в планах |
| Карточка города | Описание + чекин/удаление | + **«Хочу поехать»** + **textarea заметки** |
| Фильтры Паспорта | Нет | **4 таба**: Все / Посещённые / Непосещённые / В планах |
| Поиск в Паспорте | Нет | **Поиск + плоский список** вместо аккордеонов |
| Пустые регионы | Всегда видны | **Скрыты** при фильтре без совпадений |
| Фильтры карты | 2: Все / Посещённые | **3**: Все / Посещённые / В планах |
| Маркеры карты | 2 стиля | **3 стиля**: серый / цветной / цветной+флаг |
| Профиль | Только статистика посещений | + **счётчик «В планах: X»** |

## Модель данных (localStorage)

```json
{
  "currentTab": "passport",
  "travelerName": "Белорусский путешественник",
  "onboardingComplete": true,
  "visitedCities": {
    "mir": { "date": "2025-04-12" }
  },
  "plannedCities": {
    "brest": true,
    "pinsk": true
  },
  "cityNotes": {
    "brest": "Посмотреть крепость",
    "mir": "Замок и парк"
  }
}
```

**Инварианты:**
- `plannedCities` — `{id: true}` (O(1) lookup). Посещённый город **не может** быть в `plannedCities`.
- `cityNotes` — `{id: "text"}`. Заметка переживает удаление визита и снятие флага «В планах». Пустая заметка удаляется из объекта.
- **Чекин → авто-удаление из `plannedCities`** (если город там был).

## Принятые UX-решения

### Карточка города — лейаут (сверху вниз)
**До чекина:**
1. Описание города
2. Кнопка «Хочу поехать» (toggle, outlined → filled при активации)
3. Textarea заметки (4 строки, maxlength 500, placeholder «Ваша заметка...»)
4. Кнопка «Я здесь был»

**После чекина:**
1. Описание города
2. Textarea заметки
3. Дата визита + кнопка «Удалить отметку»

Кнопка «Хочу поехать» **скрыта** для посещённых городов.

### Поиск в Паспорте
- Ввод первого символа → аккордеоны скрываются, появляется плоский список результатов
- Каждая строка: мини-штамп (48px) + название + статусная иконка (чекмарк/сердечко/ничего)
- Очистка строки → возврат к аккордеонам с активным фильтром
- Переход между состояниями: fade 200мс

### Маркер карты «В планах»
- Цветная точка (цвет региона) + мини SVG-флаг справа-сверху (~12px в SVG-координатах)
- Цвет флага = цвет региона

### Профиль
- Под «X из 57» добавляется строка «В планах: X городов» (без прогресс-бара)

 2. **app.js — функция `saveNote(cityId, text)`:**
   - Если после `text.trim()` строка непуста → `state.cityNotes[cityId] = text.trim()`
   - Если `text.trim()` пуста → `delete state.cityNotes[cityId]`. **Проверка на пробельные символы:** триггер удаления — именно `text.trim()`, не просто `text`. Это отсекает мусорные ключи типа `{ "minsk": " " }` от случайных пробелов или переносов строк
   - `saveState()`
     - **Принудительный save при закрытии карточки:** в `closeCityCard()` добавить вызов `saveNote(activeOverlayCityId, textarea.value)` перед скрытием оверлея, чтобы не потерять последний ввод, не успевший пройти debounce
     - **Отмена debounce при закрытии:** перед принудительным save вызвать `clearTimeout(noteDebounceTimer)` чтобы избежать двойной записи в localStorage
     - **visibilitychange для заметок:** в `init()` добавить `document.addEventListener('visibilitychange', ...)` — при `document.hidden === true` проверить, открыта ли карточка города и есть ли в ней textarea. Если да — принудительно `saveNote()`. Перекрывает кейс переключения вкладки браузера
     - **pagehide для заметок:** добавить `window.addEventListener('pagehide', ...)` с аналогичной логикой — принудительный `saveNote()` при закрытии/свайпе приложения. На iOS Safari (и standalone-режиме) `visibilitychange` не гарантированно успевает отработать при force quit из панели многозадачности — процесс убивается слишком быстро. `pagehide` отрабатывает железобетонно при любых сценариях закрытия

   Текущий `renderMap()` (v1) делает `pointsLayer.innerHTML = ""` и пересобирает все 57 точек при каждом вызове. В v2 это неприемлемо — фильтры переключаются часто, а пересборка DOM тормозит на слабых устройствах. Заменить на три специализированные функции:

   - **`initMapPoints()`** — вызывается **один раз** при первой загрузке вкладки «Карта». Рендерит все 57 `<g class="map-point">` в `#map-points-layer` (hitbox + dot + flag placeholder + label).    - **`updateMapMarkers()`** — вызывается при **изменении состояния города** (чекин, удаление визита, toggle planned). Обходит все `.map-point`, проверяет `state.visitedCities[id]` / `state.plannedCities[id]` и обновляет стили точек:

       - Флаг = вертикальная линия + прямоугольник: `<line x1="0" y1="0" x2="0" y2="12" stroke="currentColor"/> <rect x="0" y="0" width="8" height="6" fill="currentColor"/>`

   - **`updateMapFilter()`** — вызывается при **переключении фильтра** (клик на `.map-filter-btn`). Не пересобирает DOM, а только toggle-ит CSS-класс `.map-point-hidden` (`display: none`) у групп маркеров. Логика:

     - `"planned"` — скрыть все, показать только `state.plannedCities[id]`
