# Архитектура этапа S1 — Фундамент

> **Этап:** S1 — рефакторинг монолита + фича «Заметки»
> **Принцип этапа:** сначала фундамент, потом этажи. Мы не строим новые фичи на
> трескающемся основании — сначала делаем основание, на котором можно строить
> в любую сторону.
> **Дата:** 2026-06-23 · **Статус:** draft

---

## 1. О чём этот документ

Это архитектурный документ конкретного этапа S1. Он отвечает на три вопроса:

1. **Что у нас есть** — продукт и код сейчас.
2. **Куда мы идём** — целевое видение и какие фичи в перспективе.
3. **Что мы делаем прямо сейчас (S1)** — рефакторинг, который делает кодовую базу
   готовой к развитию **в любом направлении**, плюс первую новую фичу (Заметки).

Общая картина продукта — в `docs/architecture-vision.md`. Здесь — глубина именно
по фундаменту.

## 2. Продукт сейчас

**«Паспорт путешественника по Беларуси»** — PWA для коллекционирования цифровых
штампов. Путешественник открывает города, получает штампы, повышает ранги,
изучает достопримечательности, планирует поездки.

| Параметр | Значение |
|---|---|
| Города | 57 в 7 регионах |
| Ранги | нет → Бронза → Серебро → Золото |
| Чек-листы | 15 топ-городов, 49 достопримечательностей |
| Вкладки | 3: Паспорт, Карта, Профиль |
| Стек | Vanilla JS, без фреймворка, без сборщика |
| Данные | `localStorage`, бэкенда нет |
| Офлайн | PWA + Service Worker |

**Что работает:** штампы и коллекция, ранги и чек-листы, карта (7 состояний
маркеров, зум, подписи), планирование (вишлист + «доисследовать»), профиль
(ордена 🥇🥈🥉, прогресс по регионам, хроника), офлайн.

**С технической точки зрения:** всё это — один файл `app.js` (~2000 строк).

---

## 3. Куда мы идём (целевое видение)

Полное видение — в `architecture-vision.md`. Кратко: бесплатное ядро захватывает и
удерживает; разовые покупки контента (аудиогиды, авторские маршруты) монетизируют;
аккаунты и синхронизация удерживают; совместное планирование (команды) расширяют;
в далёкой перспективе — CMS, AR, расширение географии.

Архитектурная цель: **слоистая модульная структура (Feature-Sliced Design)**,
которая растёт вместе с продуктом — новые фичи добавляются как новые модули в
своих слоях, не ломая существующий код.

## 5. Почему нельзя строить на монолите

Текущий `app.js` — один файл, где смешано всё: данные, состояние, рендер, карта,
события, валидация. Конкретные проблемы:

| Проблема | Последствие |
|---|---|
| **Всё в одном файле, всё глобально** | Невозможно менять одну часть, не рискуя сломать другую. Добавить Заметки = копаться в 2000 строк. |
| **Глобальный `let state`, прямой доступ** | Любой код может изменить состояние; `saveState()` вызывается вручную после каждой мутации — забыл = потерял данные. |
| **Ручная синхронизация рендера** | После изменения нужно вручную вызвать `renderPassport` + `updateMapMarkers` + `renderProfile`. Пропустил — рассинхрон. |
| **Нет границ ответственности** | Карта знает про чек-листы, карточка знает про профиль. Зависимости растут во все стороны → спагетти. |
| **Данные смешаны с логикой** | `CITIES`, `SIGHTS`, `REGIONS` захардкожены среди функций. Нельзя поменять источник данных, не трогая логику. |

**Вывод:** монолит блокирует развитие. Каждая новая фича будет стоить дороже
предыдущей, а риск регрессий — расти. Поэтому **сначала фундамент**.

## 6. Архитектура S1 (фундамент)

### 6.1 Идея

Код делится на **слои по принципу Feature-Sliced Design**. Главное правило:

> **Модуль может импортировать только то, что лежит ниже.**
> `app → widgets → features → entities → shared`

Это одно правило — гарантия того, что добавление нового модуля **никогда не сломает**
то, что ниже. Рост идёт только вверх и вширь.

### 6.2 Структура модулей

![Дерево модулей](06-target-module-tree.png)

```
src/
├── app/                      инициализация и сборка
│   ├── main.js               точка входа: load → init виджетов → switchTab → SW
│   └── store.js              экземпляр store + loadState/saveState/миграция
│
├── widgets/                  самостоятельные блоки UI (вкладки, карточки, оверлеи)
│   ├── passport-list/        коллекция штампов, поиск, фильтры
│   ├── map/                  карта: маркеры, зум/pan/pinch, подписи, фильтры
│   ├── profile/              статистика, ордена, хроника, смена имени
│   ├── city-card/            карточка города: собирает visit+checklist+plan+stamps
│   ├── onboarding/           первый запуск
│   ├── notes-list/           ← NEW: вкладка «Заметки» (S1)
│   └── note-editor/          ← NEW: редактор заметки (S1)
│
├── features/                 пользовательские сценарии (глаголы: отметить, купить…)
│   ├── visit/                отметить/удалить визит, выбор даты
│   ├── checklist/            отметить пункт чек-листа → рост ранга
│   ├── stamps/               анимация штампа, переход в коллекцию, milestones
│   ├── plan/                 вишлист / «доисследовать»
│   ├── search/               поиск и фильтры паспорта
│   └── notes/                ← NEW: создать/изменить/удалить/искать заметку (S1)
│
├── entities/                 бизнес-сущности (существительные: город, регион, заметка)
│   ├── city/                 CITIES, getCityById, getCityTier, getSightsCount…
│   ├── region/               REGIONS, REGION_ICONS, createStampSVG
│   ├── sight/                SIGHTS — чек-листы достопримечательностей
│   └── note/                 ← NEW: схема заметки, чистые хелперы (S1)
│
└── shared/                   утилиты без знания о домене
    ├── lib/
    │   ├── store-mechanism.js  createStore() — чистый механизм состояния
    │   ├── dom.js              escapeHtml, qs/qsa, showToast
    │   └── format.js           даты, нормализация поиска, плюрализация
    └── config/
        └── map-config.js       параметры проекции карты
```

### 6.3 Состояние (ядро надёжности)

Самое важное архитектурное изменение S1 — **как хранится состояние**.

| Сейчас (монолит) | После S1 |
|---|---|
| Глобальный `let state`, доступ отовсюду | Store — единая точка, доступ через API |
| `saveState()` вручную после каждой мутации (забыл = потерял данные) | `setState()` **автосохраняет** в localStorage |
| Ручной вызов `renderPassport` + `updateMapMarkers` + `renderProfile` | `subscribe()` — виджеты сами перерисовываются при изменении |
| Валидация и инварианты размазаны | `loadState` переносится **as-is** (Gold-инвариант, дедупликация milestones — уже качественные) |

```
shared/lib/store-mechanism.js    — чистый механизм (createStore), не знает о домене
app/store.js                     — экземпляр + loadState/saveState/миграция
                                   (импортит entities для валидации — имеет право, верхний слой)
entities/                        — ЧИСТЫЕ функции, state приходит аргументом
                                   (getCityTier(state, cityId)) — store не импортируют
widgets/, features/              — получают store через DI в init(store)
```

**Результат:** исчезают два класса багов — «забыл сохранить» и «забыл перерисовать».

### 6.4 Сборка

S1 вводит **Vite** — dev-сервер (горячая перезагрузка) + сборка бандла для продакшена.
Без фреймворка: код остаётся vanilla JS, Vite только собирает ES-модули.

## 7. Как S1 открывает развитие в любую сторону

> Это главное. Фундамент спроектирован так, что **любое будущее направление
> затрагивает только свои модули и не ломает остальное.**

| Будущее направление | Что добавляется | Какие слои трогает | Что НЕ трогается |
|---|---|---|---|
| **Заметки** (S1) | `entities/note`, `features/notes`, `widgets/notes-*` | entities, features, widgets | shared, app (только +notes в store) |
| **Платный контент** (S2) | `features/purchase, download, audio-player`; `widgets/paywall, audio-bar`; `shared/api/*` | features, widgets, shared | entities, app/store |
| **Обложки городов** (S2) | поле в `entities/city`, разметка в `widgets/city-card` | entities, widgets | features, shared |
| **Аккаунты** (S4) | `entities/user`; `features/auth, sync`; `shared/api/auth` | entities, features, shared | widgets (только +auth UI) |
| **Социальное** (S4) | `features/share, leaderboard, achievements` | features, widgets | entities, shared |
| **Команды** (S5) | **новый слой `processes`** сверху | новый слой | всё ниже — нетронуто |
| **Новые экраны** | **новый слой `pages`** сверху | новый слой | всё ниже — нетронуто |

**Почему это работает:** правило «импорт только вниз» означает, что новый модуль
или целый новый слой добавляется **сверху** и физически не может сломать то, что
ниже. Нижние слои (`entities`, `features`, `shared`) не переписываются при росте —
они только обрастают новыми соседями.

> Метафора: не дом, где каждую перепланировку нужно ломать стены, а конструктор —
> новые детали пристраиваются к существующим, не затрагивая фундамент.

## 8. План рефакторинга (фазы)

Каждая фаза = деплойменто-готовный шаг, поведение приложения **не меняется** до фазы
Заметок. После каждой фазы — прогон smoke-чеклиста (§10).

| Фаза | Что делаем | Результат |
|---|---|---|
| **0** | Безопасность: убрать утёкший токен из `conf`, `.gitignore`, ротация | Нет секрета в репо |
| **A** | Vite + ESM: `app.js` → `src/app/main.js`, `data-sights.js` → ESM-экспорт, bump кэша SW | Работает как модуль, поведение то же |
| **B** | Вынести чистые слои: `shared/` (utils, store-mechanism) и `entities/` (city, region, sight) с чистыми функциями | Данные и утилиты — в модулях |
| **C** | Ввести `app/store.js`: экземпляр store, loadState/saveState (as-is), автосохранение, subscribe | Исчезают баги «забыл сохранить/перерисовать» |
| **D** | Распилить `features/` и `widgets/`, декомпозировать `init()` (~315 строк → ~30). DI store в `init(store)`. Pan/zoom/pinch → `widgets/map` | Монолит `app.js` удалён, слои работают |
| **E** | Фича «Заметки»: `entities/note`, `features/notes`, `widgets/notes-list`, `widgets/note-editor`, миграция `cityNotes → notes` | 4-я вкладка работает |
| **F** *(опц.)* | Рендер на шаблонных строках + аудит `escapeHtml`; сглаживание обновлений SW (network-first для HTML) | Безопасность, быстрые обновления |

> Подробности по каждой фазе — `.kilo/plans/refactor-appjs-to-esmodules.md`.

## 9. Границы S1 (что НЕ входит)

| ❌ Не входит в S1 | Когда |

Заметок. Ни одна существующая функция не теряется.

## 10. Критерии приёмки S1

**Архитектурные:**
- [ ] `app.js` удалён, весь код — в `src/` по слоям
- [ ] Импорты идут только вниз (app → widgets → features → entities → shared)
- [ ] Состояние — через store API; нет прямого глобального `state`
- [ ] `setState` автосохраняет; `subscribe` перерисовывает
- [ ] Vite-сборка работает (dev + бандл)

**Функциональные (поведение сохранено):**
- [ ] Онбординг, ввод имени → сохраняется
- [ ] Паспорт: поиск, 4 фильтра, аккордеоны по регионам
- [ ] Карточка города → «Я здесь был» → дата → штамп
- [ ] Чек-лист: отметка пунктов → рост ранга (Бронза→Серебро→Золото)
- [ ] Планирование: вишлист, «доисследовать», флажки на карте
- [ ] Карта: pan/zoom/pinch, клик по точке, фильтры, подписи
- [ ] Профиль: статистика, ордена, хроника, смена имени
- [ ] Перезагрузка — все данные на месте (localStorage)
- [ ] Офлайн — работает из кэша

**Заметки (новое):**
- [ ] Вкладка «Заметки»: список, поиск, «+ новая», пустое состояние
- [ ] Редактор: заголовок, текст, привязка к городу, autosave, удалить
- [ ] Быстрая заметка в карточке города ↔ редактор синхронны
- [ ] Миграция: старые `cityNotes` корректно переходят в `notes`

**Безопасность:**
- [ ] В репозитории нет утёкшего токена
- [ ] `conf` в `.gitignore`
