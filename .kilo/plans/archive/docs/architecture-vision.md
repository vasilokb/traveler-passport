# Продуктовый и архитектурный вижн — «Паспорт путешественника по Беларуси»

> **Версия:** draft · **Дата:** 2026-06-22

> что заложено в перспективу. Архитектура здесь — короткая опора, а не главное.

---

## 1. Ви́джн

Путешественник по Беларуси ведёт **цифровой паспорт**: открывает города, ставит
штампы, повышает ранги (Бронза → Серебро → Золото), изучает достопримечательности,
планирует поездки и ведёт заметки. Бесплатное ядро захватывает и удерживает;
разовые покупки контента (аудиогиды, авторские маршруты) монетизируют увлечённых.

**Главная метрика успеха:** возвращаемость — чтобы человек открывал приложение
до, во время и после каждой поездки, а не удалял после первого города.

---

## 2. Пользовательский путь

```
Скачал → отметил первый город → получил штамп 🥉
   → увидел чек-лист → захотел Серебро → вернулся в город ещё раз
   → заполнил чек-лист → 🥈 → записал впечатления в Заметки
   → спланировал следующий регион → 🥇
   → захотел аудиогид по любимому городу → купил
   → показал паспорт друзьям → они поставили приложение
```

Каждый шаг — это **повод вернуться**. Ранги и коллекция штампов создают
игровую петлю; заметки и планирование — практическую пользу; платный контент —
доход с самых вовлечённых.

## 4. MVP — что получает пользователь

**Цель этапа:** доделать приложение до полноценного продукта, который
устанавливают, в нём отмечают посещения, планируют и ведут заметки.

**Состав MVP:** Тир 1 целиком (фичи 1–6 и 8 уже работают) + **фича 7 «Заметки»**
(новая). Без платного контента, без аккаунтов, без бэкенда.

Дополнительно на MVP:
- **Рефакторинг** монолита `app.js` (~2000 строк) в модульную структуру — чтобы
  фичи 7–25 было куда добавлять без боли.
- **Миграция** старых заметок `cityNotes` → новая модель `notes`.

> Подробно план MVP — `.kilo/plans/mvp-stage1-refactor-and-notes.md`.

## 5. Монетизация — платный контент

**Модель:** разовые покупки, без подписок. Контент конечен (городов ограниченное
число), подписка была бы избыточна и раздражала.

- **По городу:** аудиогид + маршруты + глубокий контент одного города — отдельная
  покупка. ~16 SKU (топ-города).
- **«Вся Беларусь»:** пожизненный бандл всех городов со скидкой.
- **Оплата:** нативные IAP через витрины магазинов (Google Play / App Store),
  валидация чеков — через RevenueCat.
- **Защита:** право на контент проверяет **сервер** (не клиент) перед выдачей аудио.

> Подробно — `.kilo/plans/1781447637026-monetization-architecture.md`.

## 6. Перспектива — как растёт продукт

Рост идёт **от фичи к фиче**, а не «сделаем всё сразу». Каждая новая фича
оправдывает конкретный архитектурный шаг:

| Этап | Триггер (фичи) | Что меняется в продукте | Что меняется в архитектуре |
|---|---|---|---|
| **S0** Сейчас | — | Бесплатное ядро работает | Монолит |
| **S1** MVP | Заметки (#7) | Полноценный бесплатный продукт | 5 слоёв FSD, Vite |
| **S2** Платное | Аудио/маршруты (#9–13) | Доход | Capacitor, RevenueCat, бэкенд CF |
| **S3** Рост экранов | Заметки разрастаются | Богаче навигация | + слой `pages` |
| **S4** Аккаунты | #14–19 | Удержание, виральность, синхронизация | auth, база данных |
| **S5** Команды | #20–21 | Совместное планирование | + слой `processes`, realtime = **полный FSD** |
| **S6+** Платформа | #22–25 | CMS, AR, расширение | отдельные сервисы |

## 7. Архитектура (опора, кратко)

Архитектура подчинена продукту и растёт вместе с ним. Полная картина:

![Целевая архитектура](04-target-architecture.png)

**Три принципа:**

1. **Единая веб-кодовая база** → Capacitor собирает её в нативные приложения
   (Android/iOS). Не пишем два приложения.

2. **Слои (Feature-Sliced Design).** Код делится по слоям, импорт — только вниз.
   MVP использует 5 слоёв; когда фичи требуют — сверху добавляются `pages` и
   `processes`. Нижние слои при этом не переписываются.

3. **Тонкий бэкенд.** Cloudflare Workers + R2 (аудио) + KV (кэш). Без базы данных,
   пока не появятся аккаунты. Сервер — только проверка прав и выдача контента.

> ⚠ **Безопасность:** в репозитории найден утёкший git-токен (`conf`).
> Удаление + ротация = Phase 0, до любой другой работы.

Эволюция слоёв по фичам — на схеме дорожной карты (`09-growth-roadmap.png`).

## 8. Дорожная карта (краткая)

```
S0 Монолит ──► S1 MVP ──► S2 Платное ──► S4 Аккаунты ──► S5 Команды ──► S6 Платформа
 (сейчас)    (Заметки)  (аудио/IAP)   (синхро/соц)   (совместно)     (CMS/AR)
```

Каждый шаг приносит пользователю новую ценность, а коду — новый слой или сервис,
**только когда этого требует реальная фича**.
