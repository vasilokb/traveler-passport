# План: Этап MVP (S0 → S1) — рефакторинг + фича «Заметки»

> Стартовый этап. Поднимаем монолит `app.js` до модульной структуры (5-слойное
> подмножество FSD) и добавляем первую продуктовую фичу — **Заметки**.
> Без платных функций, аккаунтов, бэкенда и сборщика.
>
> Связанные документы:
> - Схема 06 — целевое дерево модулей `src/`
> - Схема 07 — карта миграции (15 групп функций `app.js` → модули)
> - Схема 08 — целевой граф зависимостей слоёв
> - Схема 10 — фича «Заметки» (модель данных, экраны, слои)
> - `refactor-appjs-to-esmodules.md` — детальный план ESM-рефакторинга (основа Phase A–D)

---

## 1. Цель этапа

После завершения этого этапа приложение:
- работает как **нативные ES-модули** (без единого `app.js`), импорты идут строго
  по слоям вниз (app → widgets → features → entities → shared);
- имеет **4 вкладки**: Паспорт, Карта, **Заметки (новая)**, Профиль;
- сохраняет 100% текущей функциональности (ничего не ломаем);
- по-прежнему **без сборщика, без бэкенда, без аккаунтов** — чистый фронтенд + localStorage.

---

## 2. Что ВХОДИТ / НЕ входит

| ВХОДИТ в MVP (S1) | НЕ входит (отложено) |
|---|---|
| Рефакторинг `app.js` → 5-слойные модули (A–D) | Платные функции (IAP, аудиогиды) |
| Фича «Заметки»: вкладка + редактор + быстрая заметка | Аккаунты / кросс-девайс синхронизация |
| Миграция данных `cityNotes` → `notes` | Бэкенд (Workers/R2/KV), CMS |
| PWA-обёртка Capacitor (сборка в APK/AAB) — *опционально, см. §6* | Команды / совместное планирование |
| Phase 0 безопасности: убрать утёкший токен из `conf` | Слой `pages` (мало экранов) |

## 3. Дорожка 1 — Рефакторинг (фазы A–D)

Основан на `refactor-appjs-to-esmodules.md`. Краткая сводка фаз:

- **Phase A — Фундамент.** Внедрить Vite (dev-сервер + сборка), ESM, ESLint, структуру
  `src/`. Подключить `index.html` к точке входа. Монолит пока живёт целиком.
- **Phase B — Выделение чистых слоёв (shared, entities, app/store).** Перенос утилит
  (escapeHtml, formatDate), сущностей (sight, region, city), state-машины
  (loadState/saveState/subscribe) в модули.
- **Phase C — Фичи и виджеты.** Разрезание `app.js` по 15 группам функций
  (карта 07): features/toggleSight, features/filters, widgets/passport, widgets/map,
  widgets/profile и т.д. Точка входа `app/main.js` собирает вкладки.
- **Phase D — Чистка и линтер слоёв.** Удаление `app.js`, подключение
  eslint-plugin-import-rules (или аналог) для запрета импортов вверх по слоям,
  smoke-тесты ручные.

**Критерий готовности трека 1:** граф зависимостей кода совпадает со схемой 08;
`app.js` удалён; вкладки Паспорт/Карта/Профиль работают идентично текущим.

## 4. Дорожка 2 — Фича «Заметки»

Подробная схема — `docs/10-notes-feature.puml`.

### 4.1 Модель данных

```
note = {
  id:        string           // уникальный (Date.now()+rand)
  title:     string           // заголовок, может быть пустым
  body:      string           // текст заметки
  cityId?:   string           // необяз. ссылка на город (для быстрой заметки)
  tags?:     string[]         // необяз. теги (MVP: не более 3, свободный ввод)
  createdAt: "YYYY-MM-DD"
  updatedAt: "YYYY-MM-DD"
}
```

Хранение: `state.notes = { [id]: note }` (добавляется в `app/store.js`).

### 4.2 Миграция cityNotes → notes

Один раз при `loadState`, в порядке версий:
1. Если `state.cityNotes` есть, а `state.notes` нет → для каждого `cityId`
   создать `note { id, title: <имя города>, body: cityNotes[cityId], cityId, createdAt/updatedAt = сегодня }`.
2. Удалить `state.cityNotes`, bumps версии схемы.
3. Сохранить.

### 4.3 Размещение в слоях

| Слой | Модуль | Ответственность |
|---|---|---|
| `entities/note` | `note.js` | схема, `isValidNote`, `getNoteById`, `listNotes` (чистые функции) |
| `features/notes` | `notes.js` | `createNote`, `updateNote`, `deleteNote`, `searchNotes(query)`, `getCityNote(cityId)` — мутируют store + `saveState` |
| `widgets/notes-list` | вкладка «Заметки»: список (сорт. по `updatedAt` ↓), поиск, фильтр по городу, пустое состояние, кнопка «+ новая» |
| `widgets/note-editor` | fullscreen-оверлей: поля title/body/city-picker/tags, autosave (debounce), кнопка «удалить» |
| `widgets/city-card` | (существ.) textarea = «быстрая заметка»: при вводе вызывает `features/notes` (`getCityNote`/`updateNote`), ссылка «открыть в редакторе» |
| `app/store` | добавляет `state.notes`, миграцию, save |
| `shared/lib/*` | `format` (даты), `dom` (escapeHtml) |

### 4.4 Экраны / потоки

1. **Вкладка «Заметки»** (4-я): список карточек заметок (title, preview body,
   тег-город, дата). Поиск по title/body. Пустое состояние: «У вас пока нет заметок».
   Кнопка «+» → новый пустой note → открыть редактор.
2. **Редактор заметки** (overlay): title (input), body (textarea, длинный),
   выбор города (опционально), теги. Autosave через debounce (как текущая заметка).
   Кнопка «удалить» → confirm → `deleteNote` → возврат к списку.
3. **Быстрая заметка в карточке города**: textarea остаётся на месте; ввод
   обновляет заметку с этим `cityId` (создаётся при первом символе). Ссылка
   «открыть в редакторе» открывает full-редактор с той же заметкой.

### 4.5 Критерий готовности трека 2

- Старые заметки пользователей (cityNotes) не потеряны после обновления.
- Создание/редактирование/удаление/поиск работают офлайн (localStorage).
- Карточка города и редактор синхронизированы (одно состояние).

## 5. Порядок работ (рекомендуемый)

1. **Phase 0 (безопасность).** Убрать живой токен из `conf`, добавить `.gitignore`,
   ротировать токен на хостинге. *(Ожидает подтверждения пользователя — отдельная задача.)*
2. **Phase A–B** (фундамент + чистые слои). На этом этапе `store.js` уже знает `notes`.
3. **Phase C** — вынос Паспорт/Карта/Профиль + сборка виджетов Заметок.
4. **Phase 2 (Заметки)** — реализация features/widgets поверх готовых слоёв.
5. **Phase D** — линтер слоёв, удаление `app.js`, smoke-тесты.
6. *(опц.)* **Capacitor-обёртка** (§6).

Треки 1 и 2 идут последовательно: заметки строятся на уже готовой слоистой базе.

---

## 6. Capacitor-обёртка (опционально, конец этапа)

После стабилизации веб-версии — обернуть в Capacitor для нативных сборок.
На этом этапе Capacitor не приносит платёжной/аккаунтной логики — только
оболочка (статусбар, сплэш, иконки) и сборка APK/AAB для внутреннего теста.
Полноценная публикация в сторы и IAP — следующий этап (S2), см. план монетизации.

> Если пользователь хочет отложить нативную обёртку — весь MVP остаётся чистым PWA,
> Capacitor переносится в S2.

- [ ] Toggle достопримечательности сохраняется после перезагрузки.
- [ ] Фильтры по регионам/посещённости работают.
- [ ] Карта показывает маркеры и кластеры.
- [ ] Профиль: счётчик посещённых, сброс, экспорт/импорт данных.
- [ ] **Заметки**: создать, отредактировать, удалить, найти через поиск.
- [ ] **Заметки**: быстрая заметка в карточке города ↔ редактор синхронны.
- [ ] **Миграция**: старые данные с `cityNotes` корректно переходят в `notes`.
- [ ] Импорт старого дампа (v0) не падает.
- [ ] Офлайн-режим (PWA) работает после первой загрузки.
- [ ] ESLint-проверка слоёв: нет импортов вверх.
- [ ] В `conf` / репозитории нет утёкшего токена.

## 8. Инварианты этапа

- Без сборки-обфускации исходников пользователя (код открыт).
- Без аккаунтов и сервера — всё локально, как сейчас.
- Граф зависимостей соответствует схеме 08 (импорты только вниз).
- Ни одна существующая функция не теряется (паритет с текущим монолитом).
