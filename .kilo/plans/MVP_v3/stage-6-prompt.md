## Задачи

### 1. `sw.js` — обновить кэш

**Единственная правка кода на этом этапе.** Две строки.

**Строка 1:**
```javascript
// Было:
var CACHE_NAME = 'belarus-passport-v2';
// Стало:
var CACHE_NAME = 'belarus-passport-v3';
```

**Строки 2–10 (массив ASSETS):** Добавить `data-sights.js` после `app.js`:

```javascript
var ASSETS = [
  './',
  'index.html',
  'style.css',
  'app.js',
  'data-sights.js',
  'manifest.json',
  'icon-192.svg',
  'icon-512.svg'
];
```

> **⚠️ `cache.addAll()` — all-or-nothing:** `event.waitUntil(caches.open(CACHE_NAME).then(cache => cache.addAll(ASSETS)))` — если хоть один файл из ASSETS не существует, **весь** `addAll` отклоняется, и SW не устанавливается. Поэтому:
> - Добавляй в ASSETS **только существующие файлы**
> - `data-sights.js` существует ✓
> - `covers/*.webp` — **НЕ добавляй**, директория не существует. Когда обложки будут созданы (пост-MVP), нужно либо добавить их в ASSETS по одной, либо переключиться на per-asset `cache.add()` с `.catch()`
>
> **⚠️ Bump `v2` → `v3`** заставит SW удалить старый кэш (`belarus-passport-v2`) при `activate` и закэшировать все файлы заново под новым именем. Пользователи автоматически получят обновление при следующей загрузке благодаря `skipWaiting()` + `clients.claim()`.
>
> **⚠️ `file:///` протокол:** Service Worker не работает на `file:///` (требует http/https/localhost). Приложение корректно работает без SW в этом режиме — `data-sights.js` загружается обычным `<script>`, offline-кэш просто недоступен. Это известное ограничение, не баг.
