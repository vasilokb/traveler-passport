# Паспорт путешественника по Беларуси — Implementation Plan v2

## Контекст

Мобильное веб-приложение для коллекционирования штампов городов Беларуси.
**Платформа:** мобильный веб (390–430dp, портрет, тап 44×44pt).
**Данные:** localStorage, без бэкенда.
**MVP-документ:** `MVP.md` (Редакция 4.2, финальная).
**Запуск:** локальный сервер (`npx serve .` или Live Server в VS Code). Открытие `index.html` напрямую через `file://` не поддерживается — браузеры блокируют загрузку внешних `style.css` / `app.js` по CORS.

---

## Ключевые архитектурные решения

| Вопрос | Решение |
|--------|---------|
| Структура файлов | **3 файла:** `index.html`, `style.css`, `app.js` (не однофайловый) |
| SVG-карта | Готовая open-source контурная SVG + JS-функция проекции (Меркатор) для размещения 57 точек по GPS-координатам |
| Штампы | Единая SVG-структура (круг/зубчатый контур), дифференциация по цвету региона + уникальная минималистичная иконка |
| Описания городов | JSON-массив генерируется LLM, зашивается в `app.js` на Этапе 1 |
| Идентификация городов | Стабильный латинский `id` (`minsk`, `mir`, `nesvizh`). Кириллица — только для отображения |
| Навигация | Глобальная переменная `currentTab` + `activeOverlayCityId`. Без стека истории |
| Будущие даты | `<input type="date" max="сегодня">` — выбрать будущую дату невозможно |

## Модель данных (localStorage)

```json
{
  "travelerName": "Белорусский путешественник",
  "visitedCities": {
    "mir": { "date": "2025-04-12" },
    "lida": { "date": "2026-05-31" }
  }
}
```

`nameRu` хранить в `visitedCities` **не нужно** — имя берётся из справочника `CITIES` по `id`.

## Навигационная модель

```
Глобальное состояние:
  currentTab: 'passport' | 'catalog' | 'map' | 'profile'
  activeOverlayCityId: string | null   // карточка города открыта
  stampOverlayCityId: string | null     // экран «Штамп получен» открыт
  stampOrigin: 'catalog' | 'map' | 'passport' | null  // откуда пришли к чекину
```

- Закрытие экрана «Штамп получен» тапом по свободному месту → `stampOverlayCityId = null`, пользователь видит текущий `currentTab`.
- Кнопка «В коллекцию» → `currentTab = 'passport'`, раскрывается нужный аккордеон, скролл к штампу.

## Этапы реализации

### Этап 1. Каркас, справочник городов, Каталог

**Файлы:** `index.html`, `style.css`, `app.js`

**Задачи:**
1. Создать `index.html` с главным контейнером (`max-width: 430px`, центрирован), 4 секциями-вкладками и нижним Tab Bar.
2. Создать `style.css` с мобильной стилистикой, все active-элементы ≥ 44×44px.
3. В `app.js` создать массив `CITIES` (57 городов с полями `id`, `name`, `region`, `lat`, `lon`, `description`). Описания генерируются LLM.
4. В `app.js` создать массив `REGIONS` (7 регионов с `id`, `name`, `color`, `accent`, `accentType`).
5. Реализовать рендер Каталога: список городов, сгруппированный по регионам, под вертикальный скролл.
6. Реализовать переключение вкладок через Tab Bar (заглушки для Паспорта, Карты, Профиля).
7. Реализовать объект `visited` в localStorage и функции `saveState()` / `loadState()`.
8. **⚠️ Временная механика (УДАЛЯЕТСЯ на Этапе 4):** клик по городу в Каталоге переключает статус visited (toggle) с текущей датой. Это противоречит финальному MVP и существует только для проверки localStorage на ранних этапах. **Полностью удаляется** при реализации Этапа 4.

**Критерии готовности:**
- [ ] 3 файла открываются локально, контент центрирован в мобильные рамки.
- [ ] Выводятся все 57 городов, сгруппированных по 7 регионам.
- [ ] Клик по городу toggles статус visited, состояние сохраняется после перезагрузки.
- [ ] Tab Bar переключает видимые секции (заглушки ок).

---

### Этап 2. Профиль, онбординг, статистика

**Задачи:**
1. Реализовать экран онбординга: модалка/оверлей при первом входе с полем ввода имени и кнопкой «Пропустить». Если пропущено — `travelerName = "Белорусский путешественник"`.
2. Реализовать экран Профиля: имя (кликабельно для редактирования), общий прогресс «X из 57», 7 прогресс-баров по регионам.
3. Реализовать Хронику визитов: список посещённых городов, сортировка по дате визита (новые → старые), при совпадении дат — по алфавиту.
4. Статистика пересчитывается реактивно при любом изменении `visitedCities`.

**Критерии готовности:**
- [ ] Онбординг появляется только при первом входе (проверка наличия записи в localStorage).
- [ ] Имя можно пропустить, затем отредактировать в Профиле.
- [ ] Общий счётчик и прогресс-бары корректны.
- [ ] Хроника показывает посещённые города в правильном порядке.

---

### Этап 3. Экран «Мой паспорт» — аккордеоны и штампы

**Задачи:**
1. Реализовать 7 региональных аккордеонов (CSS Grid внутри). Тап по заголовку — раскрытие/сворачивание.
2. Ячейки городов: непосещённые — серые силуэты, посещённые — цветные (цвет региона + мини-иконка штампа).
3. Реализовать геймификацию: 100% закрытие региона → золотая метка «Пройден» на обложке аккордеона. Для Минска (1 город) — серебряная метка «Старт».
4. Тап по ячейке города → открытие карточки города (пока заглушка, реализуется в Этапе 4).

**Критерии готовности:**
- [ ] Аккордеоны плавно раскрываются/сворачиваются.
- [ ] Посещённые города отображаются как цветные штампы, непосещённые — серые.
- [ ] Золотая/серебряная метка появляется строго при 100% закрытия региона.
- [ ] При удалении города (через временный toggle в Каталоге) золотая/серебряная метка региона автоматически снимается. На Этапе 4 эта же логика проверяется через кнопку «Удалить отметку» в карточке города.

---

### Этап 4. Карточка города и осознанный чекин

**Задачи:**
1. Реализовать карточку города как динамический оверлей: название, регион, описание.
2. Если город не посещён — кнопка «Я здесь был». При нажатии — модальное окно с `<input type="date" max="сегодня">` (по умолчанию — сегодня). После подтверждения — город записывается в `visitedCities` и вызывается экран «Штамп получен».
3. Если город посещён — отображается дата визита и кнопка «Удалить отметку». Удаление: сброс из `visitedCities`, пересчёт статистики, снятие ачивок.
4. **Рефакторинг Каталога:** клик по городу открывает карточку, больше не меняет `visited` напрямую. Тап по штампу в Паспорте — тоже открывает карточку. **Удалить временную toggle-механику из Этапа 1.**
5. Сохранять `stampOrigin` (откуда пришли: catalog / map / passport) для корректного возврата с экрана «Штамп получен».

**Критерии готовности:**
- [ ] Тап по городу в Каталоге или Паспорте открывает карточку с описанием.
- [ ] Отметка требует выбора даты (не позже сегодняшнего дня).
- [ ] «Удалить отметку» полностью сбрасывает город во всех экранах.
- [ ] Каталог больше не меняет visited напрямую.
- [ ] Временная toggle-механика из Этапа 1 полностью удалена из кода.

---

### Этап 5. Экран-эмоция, Карта, фильтры

#### 5a. Экран «Штамп получен»

**Задачи:**
1. Полноэкранный оверлей после подтверждения даты. Крупный штамп с CSS-анимацией «впечатывания» (scale + rotate).
2. Кнопка «Поделиться» — Web Share API (fallback на ПК: копирование текста в буфер + тост «Ссылка скопирована»).
3. Кнопка «В коллекцию» → `currentTab = 'passport'`, раскрыть аккордеон региона, которому принадлежит город (определяется через `CITIES.find(c => c.id === cityId).region`), скролл к подсвеченному штампу.
4. Тап по свободному месту → закрыть оверлей, вернуться на `currentTab` (без раскрытия аккордеонов).

#### 5b. Интерактивная Карта

**Задачи:**
1. Найти и интегрировать open-source контурную SVG-карту Беларуси (желательно с границами областей, но не критично — для размещения точек достаточно контура страны). Источник: Wikimedia Commons / GitHub.
2. Написать JS-функцию проекции GPS → SVG-координаты для размещения 57 интерактивных точек (хитбокс ≥ 44×44px).
3. Точки синхронизированы с localStorage: посещённые — цветные, непосещённые — серые. Тап → карточка города.
4. Фильтр «Все / Посещённые» над картой.
5. Empty state: фильтр «Посещённые» при 0 отметок → плашка-подсказка.

#### 5c. Фильтры и пустые состояния в Каталоге

**Задачи:**
1. Табы-фильтры: «Все / Посещённые / Непосещённые».
2. Поиск по названию города.
3. Empty state «Посещённые» при 0: *«Здесь появятся города...»*
4. Empty state «Непосещённые» при 57/57: *«Ура! Вы прошли всю Беларусь!»*

**Критерии готовности (весь Этап 5):**
- [ ] Анимация штампа срабатывает при чекине.
- [ ] «В коллекцию» переводит на Паспорт, раскрывает нужный регион, скроллит к штампу.
- [ ] Тап по свободному месту возвращает на предыдущий экран.
- [ ] Карта отображает 57 точек корректно, фильтр и empty state работают.
- [ ] «Поделиться» генерирует текст / копирует в буфер.
- [ ] Фильтры и поиск в Каталоге работают, заглушки показываются вовремя.

### Этап 6. Стабилизация и QA

**Проверяемые сценарии:**

1. **Первый вход:** онбординг → пропуск → дефолтная заглушка. Редактирование имени в Профиле.
2. **Полный цикл:** открытие карточек, отметка 15+ городов — проверка стабильности Хроники и UI.
3. **Даты:** чекин с датами из прошлого (раньше → позже → раньше) — правильность сортировки в Профиле. Будущие даты заблокированы.
4. **Каскадное удаление:** удаление штампа из Карточки → исчезновение из Паспорта, Карты, Хроники, уменьшение счётчиков.
5. **Ачивки:** закрытие области → золотая метка. Удаление одного города → автоматическое снятие метки.
6. **Навигация:** тап по свободному месту «Штамп получен» → возврат на корректный `currentTab`.
7. **Мобильный UX:** проверка на реальном смартфоне (тап по точкам SVG, нативный календарь в модалке).
8. **Автономия:** перезагрузка страницы → данные в localStorage на месте.

## Риски и открытые вопросы

| Риск | Митигация |
|------|-----------|
| SVG-карта может потребовать ручной адаптации | Найти контурную карту заранее, желательно с областями; для размещения точек достаточно контура страны |
| 7 уникальных иконок штампов — субъективное качество | Для MVP достаточно минималистичных силуэтов, уточнять в процессе |
| `input type="date"` на старых Android-браузерах | Проверить на целевых устройствах, при необходимости — кастомный пикер |
| Web Share API не поддерживается в некоторых браузерах | Fallback — копирование в буфер, уже заложено в плане |
